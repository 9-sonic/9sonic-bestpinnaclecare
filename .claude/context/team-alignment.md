## Unifying minds without dictating method

We align on:

- **Product truths** (honest tap, one record, offline normal, audit on correction, location at clock only)  
- **Visibility rails** (Linear + GitHub)  
- **Coarse sprints** (1 and 2)  
- **Named ownership** of client vs craft vs environment  

We do **not** align by:

- Pre-declaring exact implementation order  
- Assigning methods to specialists  
- Inventing backlogs to create false certainty  
- Micromanaging days or hours  

**Align, don’t control.**

---

## When work appears

1. Capture **outcome** in Linear (`BES-xxx`).  
2. Branch + PR linked to the ticket for code.  
3. Review with product truths in mind.  
4. Merge and mark status honestly.  
5. Record durable decisions in Notion if needed.  

Uncertainty → use skills (`uncertain-work`, `issue-handling`), not fake plans.

## What success feels like

- Everyone can see what’s in flight without asking permission to look.  
- Specialists still choose how to build.  
- Client hears the same story the code protects.  
- PM unblocks paths instead of owning solutions.  
- Design improves what exists, in conversation with FE.  
- Sprint language stays coarse; iteration stays real.  

---

## Anti-alignment (reject)

- “No designer / PM will just decide UI in code forever” as default without Athaliah  
- “PM owns the architecture”  
- Notion as the board  
- Day-by-day kits or invented mega-backlogs  
- Continuous location tracking rationalised as care safety without process  
- Silent dual records on retry  

This file is a compass, not a contract rewrite. When it conflicts with an explicit team decision on a ticket, follow the ticket and update kit docs if the team wants the compass changed.
