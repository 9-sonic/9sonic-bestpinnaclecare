# Skill: Repo conventions — how not to collide

**Purpose:** Give every person the *same* picture of this repo, so two people
using Claude on different machines produce work that fits together instead of
fighting. Most of what went wrong here was not bad code — it was two people
holding different mental models of where things live.

**Use when:** Starting any change, creating a file in a new place, adding a
dependency or workflow, or when CI fails for a reason that is not your code.
**Load this before writing code, not after CI goes red.**

---

## 1. The layout is the contract

```
/                    Rails 8 API  — app/ config/ db/ lib/ spec/ Gemfile
/client/pwa          carer mobile PWA
/client/admin-web    manager website
/contracts           shared API shapes
/swagger/v1          generated OpenAPI — DO NOT hand-edit
/docs                process and delivery notes
/.claude             this project brain
```

**There is exactly one home for each thing.** Do not create `backend/`, `pwa/`,
`admin-web/` or `frontend/` at the root — an earlier sketch used those names,
both shapes ended up alive at once, and CI spent weeks validating a directory
that did not exist while failing every correct PR. The **Repo hygiene** job now
rejects those names outright.

If you genuinely need a new top-level directory, it is **not a free choice** —
change these three in the same PR or the next person's CI breaks:

1. `.github/workflows/ci.yml` — path filters and the job that builds it
2. `.github/labeler.yml` — `scope:*` labels
3. `.github/workflows/deploy.yml` — what gets shipped where

Say so explicitly in the PR description. A reviewer should never discover a new
top-level directory by reading the file list.

## 2. Before you start — 60 seconds that prevents a conflict

```bash
git fetch origin && git log --oneline origin/main -5   # what landed since?
gh pr list --state open                                # who is already in here?
```

- **Someone else's PR touching your files?** Say so on both PRs *now* and agree
  who goes first. Two people rebasing 3,000 lines against each other is a lost
  afternoon.
- **Claim the ticket in Linear** (`BES-xxx`) before branching. A silent branch is
  invisible to Jesse and Gichogu, and invisible work gets duplicated.
- **Branch from fresh `main`**, never from another feature branch unless you
  deliberately mean to stack — and if you stack, say so in the PR body and set
  the base branch accordingly.

```
feat/BES-123-short-slug     fix/…     chore/…     docs/…
```

## 3. Single sources of truth (the duplication traps)

| Thing | The one source | Never |
| --- | --- | --- |
| API spec | `swagger/v1/swagger.yaml`, generated by rswag from `spec/requests/api/v1/docs/*_spec.rb` | A second `swagger.yaml` inside a client folder — the copies drift and nobody knows which is real |
| Build output | Generated at deploy time | `dist/`, `dev-dist/`, `node_modules/` committed — CI rejects these |
| Secrets | GitHub Actions secrets → `env:` → `ENV.fetch` | A literal in a committed file. See [[secrets-and-history]] |
| Task status | Linear `BES-xxx`, mirrored by the GitHub board | Status that only exists in WhatsApp |
| Merge truth | The GitHub PR | A branch you pushed and assumed landed |

**The contracts rule:** a PR that changes `/contracts` without a matching change
in `/client` or the Rails root is incomplete. State which PR completes the
handshake.

## 4. What CI actually checks (so red is never a surprise)

| Job | Fails when |
| --- | --- |
| **Repo hygiene** | Stray top-level app dir · committed build output · committed `.env` · a required directory missing |
| **backend (Rails)** | RuboCop, Brakeman (high confidence) or RSpec fails. Runs on `app/ config/ db/ lib/ spec/ swagger/ Gemfile*` |
| **client/pwa**, **client/admin-web** | lint, typecheck, build or test fails in that folder |
| **contracts** | a document under `/contracts` does not parse |
| **Template gate** | no `Closes #N` (or `Process-only: true`), no scope ticked, UI change with no screenshot |
| **Gitleaks** | a credential in **any** commit — history is scanned, not just your diff |

Run the backend checks locally before pushing — they are the same commands:

```bash
bin/rubocop && bin/brakeman --no-pager && bundle exec rspec
```

**A red check is information, not an obstacle.** Do not disable a check, add
`|| true`, or merge around it. If a gate is wrong, fix the gate in its own PR
and say why — that is a reviewable decision. Silently weakening it is not.

## 5. Never rewrite what other people are standing on

- **No direct pushes to `main`.** Reviews and gates only run on a PR; a bare
  push skips them. Branch → PR → green → merge.
- **No `--force` / `filter-repo` on a shared branch.** Every clone breaks, every
  open PR needs rebasing, and SHAs referenced elsewhere stop matching. This repo
  has already been damaged once this way. If you think it is genuinely needed,
  it is Jesse's and Gichogu's call, announced first.
- **Do not delete issues, branches or history to tidy up.** The record is the
  point.
- Rebase *your own* unpushed branch freely; that is not what this is about.

## 6. Writing GitHub Actions (where this repo has been bitten)

- `secrets` is **not available in `if:`**. `if: secrets.FOO != ''` does not
  evaluate to false — GitHub rejects the whole workflow with *Unrecognized
  named-value: 'secrets'*. Guard **inside** the step:
  ```yaml
  env:
    FOO: ${{ secrets.FOO }}
  run: |
    if [ -z "${FOO:-}" ]; then echo "not configured — skipping"; exit 0; fi
  ```
- **Never interpolate `${{ github.event.* }}` into a `run:` block.** PR titles
  and branch names are attacker-controlled; that is a script-injection path, and
  an apostrophe in a title breaks the command anyway. Pass through `env:` and
  build JSON with `jq`.
- An optional integration with nothing configured should **skip and stay green**,
  never fail someone's PR.
- Changing a path filter? Re-read §1 — the three files move together.

## 7. When you are not sure

Say so, in the PR or the ticket, and name who decides:

| Question | Owner |
| --- | --- |
| Business policy (grace periods, location strictness, timesheet period) | Jesse ↔ Best Pinnacle |
| Environment, access, board hygiene, automation health | Gichogu |
| Backend records, authz, offline/idempotency semantics | Ian |
| UI behaviour and states | Dennis, with Athaliah on design |

Claude should **surface the options and the trade-off**, not pick for the
specialist. Implement the smallest reversible default, mark the open question in
the PR, and move on — do not hard-code an unconfirmed client policy.
