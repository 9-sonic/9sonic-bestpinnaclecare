## How to use skills well

1. **Match the situation**, don’t load everything.  
2. **Prefer templates inside skills** over inventing new process docs.  
3. **Keep flexibility**: skills are shapes; specialists fill methods.  
4. **Keep accountability**: almost every skill ends in Linear and/or GitHub visibility.  
5. **Keep everyone in view**: CEO, PM, design, FE, BE all appear across the set.

## What skills are not

- Not a sprint plan  
- Not a prioritised backlog  
- Not permission to expand into unrelated care-platform modules  
- Not a replacement for human judgment on client policy  

If a skill conflicts with an explicit human decision in a ticket or PR, **follow the human decision** and suggest updating the skill only if the team wants the kit changed.
